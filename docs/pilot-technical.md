## Проверки интеграционной версии

- Unit-тесты JavaScript, secrets, worker, ai_modes и mail — проходят.
- Обычный e2e — 62 проверки; Supabase e2e — 113 проверок с реальными SQL-функциями на локальном PostgreSQL 17.
- Визуальный набор — 275 проверок, включая 56 для геометрии в четырёх скинах на 1440 и 390 px.
- Кабинеты — 21 браузерная проверка с заголовками из `vercel.json`: печать без передачи пароля в адресе, профиль, код связи, группа, задание, Пульс, отзыв ссылки, администратор, CSV и выход.
- SQL накатывается повторно. Отдельные транзакционные сценарии проверяют чужие данные, просроченные/повторные ссылки, бюджет, журнал и запрет записи во время обслуживания.
- Локальный нагрузочный стенд создаёт собственную `vk_load_*`, использует настоящие SQL-функции и HTTP, запускает только заглушку модели и удаляет БД после теста. В отчёте — 100 входов, 1000 синхронизаций, 20 запросов ИИ. Проверка p95 относится к этому стенду, а не к ещё не выбранному рабочему хостингу.
- Скриншоты интеграционной версии с искусственными данными — `docs/art/pilot-checks/`. Они показывают всю цепочку, а не изолированные промежуточные ветки.

В процессе общей приёмки устранены ошибки первого нажатия в профиле, конфликт SQL-имени FOUND в Пульсе, наследование нижней навигации на мобильных кабинетах, повторное открытие отозванной ссылки и повторное списание расхода при сетевом повторе. Финальная ветка включает эти исправления вместе с воспроизводящими сценариями; промежуточные черновики не объявлены выпуском.
