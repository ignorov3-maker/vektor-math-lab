# AGENTS.md — правила для Codex

«Вектор» — веб-платформа по математике для 5–9 класса. Ядро — «Рентген мышления»: находим неверное правило в голове ребёнка («жучок мысли») и помогаем его победить. Маскот — пиксельный Бипыч (идентификатор в коде — `VEKTOR_DROBIK`, исторически).

## Стек
Статический сайт без сборки: `index.html`, `app.js`, `content/*.js`, `style.css`, `skins.css`. Чистый JavaScript без фреймворков; модули отдают себя через `window.VEKTOR_*`. Хостинг — Vercel (выкладка из `main`, предпросмотр для PR), данные — Supabase. Цвета бренда — переменные в `:root` файла `style.css` (`--green`, `--ink`, `--paper`, `--marker`, `--margin`). Четыре скина: тетрадь, орбита, стикеры, пиксель — графика должна выглядеть прилично во всех.

## Образ маскота
Решение владельца: пиксельный Бипыч заменил робота из исходного ТЗ (подробности — `docs/art/HANDOFF.md`). Ниже — исходный образ, сохранён для истории.

Небольшой округлый робот. Голова — экран, эмоции — глаза на экране. Антенна в форме «/» (знак дроби). На животе круглый индикатор заряда, разделённый на доли, как пицца: закрашенные доли = решённые задачи цели дня. Цвета: зелёный `#1E7358`, белый, жёлтый `#FFE58A` (заряд), коралловый `#E46A5E` (жучки). Характер: любопытный, смелый, сам иногда ошибается, на «ты», никогда не ругает. Дизайн оригинальный, не похожий на известных персонажей.

Жучки — маленькие милые (не страшные) персонажи, у каждого черта, напоминающая ошибку. Список ключей — в `docs/contracts.md`.

## Правила
1. Одна задача — одна ветка `codex/<задача>` от свежего `main` — один PR в `main`. Свои PR не сливать: сливает владелец.
2. Менять **только** свои файлы: `assets/**`, `content/drobik.js`, `content/art.js`, `content/collection.js`, `styles/drobik.css`, `board.html`, `landing/**`, `print/**`, `docs/art/**`, `tests/codex_*.py`.
   Общие файлы (`index.html`, `app.js`, `style.css`, `teacher.html`, остальные `content/*`, `supabase/*`) не трогать — подключение делает Claude.
3. Никаких внешних ресурсов: Google Fonts, CDN, аналитики, npm-зависимостей, шага сборки.
4. Графика оригинальная, без чужих брендов и персонажей. Сгенерированные картинки — только концепты в `docs/art/`; в продукт идёт чистый SVG.
5. Анимации — CSS, отключаются при `prefers-reduced-motion`. Вся графика маскота и жучков — до 400 КБ, до 15 КБ на состояние маскота.
6. Не делать логику учёбы, проверки ответов и сервера — это зона Claude.
7. Не придумывать цифры и отзывы для лендинга и слайдов (заглушка «скоро»).
8. Контракт (`docs/contracts.md`) меняется только отдельным PR.

## Задачи пилота CX-12…CX-26

Для задач CX-12…CX-26 ограничения правил 2 и 6 снимаются в пределах соответствующего задания. Помимо ранее разрешённых файлов можно менять `AGENTS.md`, `supabase/**`, `app.js`, `index.html`, `teacher.html`, `config.js`, `content/visuals.js`, `content/program.js` и создавать или менять `parent.html`, `tutor.html`, `report.html`, `tools/migrate/**`, `vercel.json`, `server/**`, `legal/**`, `tests/**`, `.github/workflows/tests.yml`. Дополнительные файлы, прямо перечисленные в задании пилота (например, `style.css` в CX-19 и `docs/migrate.md` в CX-24), разрешены только в рамках этого задания.

Правила 1, 3, 4, 5, 7 и 8 остаются в силе. Единственное исключение из правила 3 — скрипт Яндекс SmartCaptcha на страницах регистрации и восстановления пароля. Одна задача — одна ветка `codex/cx-NN-...` от свежего `main` — один PR. Задачи идут по порядку CX-12 → CX-26; свои PR не сливать. Перед стартом владелец проверяет и сливает PR #23 (CX-11) и ветку `claude/remove-stray-log`.

### База, доступ и секреты

- Каждая новая SQL-функция: `security definer`, `set search_path = public, extensions`; затем `revoke ... from public, anon, authenticated` и `grant` только необходимых прав. Браузеру доступны только нужные RPC.
- На каждой новой таблице включён RLS, прямой доступ `anon` запрещён. Проверку прав нельзя подменять фильтрацией в браузере.
- На каждую новую SQL-функцию — сценарий в `tests/supabase_scenarios.py`, включая попытку доступа к чужим данным.
- Секреты OpenRouter, `service_role`, почты и капчи — только в секретах Supabase. В `config.js` разрешён только публичный ключ `anon`. Не вставлять секреты в код, тесты, документацию, логи или PR. `node tests/secrets.test.js` проверяет текстовые файлы репозитория; значения находок в вывод не попадают.
- Боевую базу напрямую не менять. SQL-изменения оформлять файлами в `supabase/` через PR; на боевую базу их применяет владелец после слияния.
- Проверять на демо-классе и тестовой базе, не входить под настоящими аккаунтами учеников пилота. Старые логины и прогресс должны сохраниться.

### Проверки пилота перед каждым PR

```
node tests/secrets.test.js
node tests/stubs.test.js
python tests/e2e_scenarios.py
python tests/supabase_scenarios.py   # локальный Postgres 14+, подключение в VEKTOR_PG
bun tests/ai_modes.test.ts           # если менялась функция tutor
```

Если локально нет нужной среды, указать непрошедшую проверку и причину в PR, не называть её успешной. Для изменений интерфейса приложить скриншоты компьютера и телефона 390 px; проверить предпросмотр Vercel. Автотесты должны быть зелёными до слияния владельцем.
